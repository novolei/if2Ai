### A.5 — LLM-augmented insight extraction

- **What:** Extend `SelfReflector` to call `UtilityLlm::complete` with a trajectory summary and parse JSON insights. Existing half-stub `augment_failure_insights_with_llm` in `reflector.rs` can be finished.
- **Trigger to start:** real usage shows reflect step's `extracted` is consistently low or `promoted` ratio is unsatisfying despite multiple repeat-pattern runs. Numbers to watch: <1 promoted per week, OR procedural memory not growing when failures happen.
- **Cost:** 1 extra LLM call per cycle (cheap on Haiku, but multiplies if cycles fire often).
- **Scope estimate:** small (~100-200 LOC) — the trait + collector + UtilityLlm shim + prompt template all exist.
- **Risk:** spam procedural memory with low-quality LLM-generated insights. Mitigation: same 0.7 confidence floor + a per-cycle cap.

#### `commands/mod.rs` AppState refactor (RD-02, P1)

- **Status:** `AppState` struct accumulated 25+ fields (`session_manager`, `tool_registry`, `project_manager`, `permission_senders`, `permission_overrides`, `stream_cancel_senders`, `memory_provider`, `context_budget`, `trajectory_manager`, `learning_module`, `active_retrieval_manager`, `harness`, `threat_scanner`, `job_runner`, `utility_llm`, `summary_store`, `rolling_summarizer`, `pinned_store`, `memory_compiler`, `memory_ticker`, `learned_traits`, `daydream_coordinator`, `trajectory_collector` — and that's just memory-related). PR #2 introduced `ServiceRegistry` for SessionManager/ToolRegistry/ProjectManager but stopped there.
- **Why important:** every new feature adds another field. AppState is becoming the "junk drawer" antipattern. Adding fields via PR #4/#10 was a full plumbing exercise.
- **Direction:** group into 3-4 cohesive registries (memory, learning/evolution, runtime, control_plane). Or use the dependency-injection pattern fully.
- **Scope estimate:** large (multi-PR refactor). Not a quick win.
- **Risk:** high — touches every command handler. Should brainstorm carefully.

#### `lib/tauri.ts` DTO extraction (GF-04 / RD-01, P1)

- **Status:** `src/lib/tauri.ts` is **3,151 LOC**. Mix of legacy DTO definitions, transport bridge, and command facade. CLAUDE.md hard-rules new code against importing from here.
- **Why important:** every new frontend feature needs to pick "use `src/api/*` or extend `lib/tauri.ts`?". Without splitting, the legacy keeps growing.
- **Direction:** classify DTO definitions by domain (memory / projects / sessions / ...) and migrate to `src/transport/contracts.ts` or per-domain files; transport adapters move under `src/api/*`.
- **Scope estimate:** medium-large (multi-PR, can be incremental).
- **Risk:** moderate — types-only changes are mostly safe but volume is large.
